CELESTE SAVE FIELD INFORMATION

Purpose:
This file describes known Celeste .celeste save fields so BackDoor can evaluate user edits.
Do not treat this file as a fixed risk list. Use it as schema/context.
Risk should be generated by comparing the user's changed value to the expected type, range, structure, and behavior of the field.

Source notes:
- Celeste savefiles are stored as XML 1.0 files.
- Savefiles use the .celeste extension.
- Savefiles are located in a Celeste/Saves/ folder.
- Save slots are numbered starting at 0: 0.celeste is the first save slot, 1.celeste is the second, etc.
- Celeste may ignore invalid values or behave abnormally when invalid values are written.
- This file includes both documented knowledge and observations from an example save file.

GENERAL XML STRUCTURE

Root element:
SaveData

The SaveData element contains global/profile-level values such as:
- Version
- Name
- Time
- LastSave
- CheatMode
- AssistMode
- VariantMode
- Assists
- TheoSisterName
- UnlockedAreas
- TotalDeaths
- TotalStrawberries
- TotalGoldenStrawberries
- TotalJumps
- TotalWallJumps
- TotalDashes
- Flags
- Poem
- SummitGems
- RevealedChapter9
- LastArea
- Areas

General rule:
Values above Areas are mostly global save/profile fields.
Values inside Areas are chapter-specific progress data.

GENERAL VALUE RULES

Boolean fields:
- Expected values: true or false.
- Suspicious values: yes, no, 0, 1, text, empty value, numbers, null.
- Celeste XML writes booleans as lowercase true/false.

Integer fields:
- Expected values: whole numbers.
- Suspicious values: decimals, text, booleans, empty value, negative values unless specifically expected.

String fields:
- Expected values: text.
- Suspicious values: empty value if the field normally has a required/default string, huge text, XML-breaking characters if not escaped.

FileTime fields:
- Expected type: integer.
- Expected meaning: 100-nanosecond intervals.
- For playtime duration, divide by 10000 to get milliseconds.
- Suspicious values: negative numbers, text, booleans, decimals, extremely small or impossible values if meant to represent playtime.

Attribute-only elements:
- Some XML elements have no inner text and store data as attributes.
- Example: LastArea ID="1" Mode="Normal".
- Suspicious edits: deleting attributes, renaming attributes, using invalid IDs/modes.

List elements:
- Some elements contain repeated child elements.
- Example: Poem contains multiple string children.
- Example: SummitGems contains multiple boolean children.
- Example: Areas contains multiple AreaStats children.
- Suspicious edits: changing list element type, deleting required list structure, replacing a list with plain text.

KNOWN TOP-LEVEL FIELDS

Field: Version
XML path: SaveData.Version
Observed example: 1.4.0.0
Expected type: string
Known behavior: Version of the Celeste game/client.
Reasonable edits: Usually leave unchanged.
Suspicious edits: empty value, random text, changing version without reason.

Field: Name
XML path: SaveData.Name
Observed example: Madeline
Expected type: string
Known behavior: Name of the savefile. Defaults to Madeline.
Reasonable edits: short text name.
Suspicious edits: empty string, very long text, XML-breaking characters if not escaped.

Field: Time
XML path: SaveData.Time
Observed example: 764888480000
Expected type: integer FileTime duration
Known behavior: Total duration of time spent playing Celeste. Measured in 100-nanosecond intervals.
Conversion note: milliseconds = Time / 10000.
Reasonable edits: non-negative integer.
Suspicious edits: negative number, text, boolean, decimal, empty value, unrealistically huge value.

Field: LastSave
XML path: SaveData.LastSave
Observed example: 0001-01-01T00:00:00
Expected type: string timestamp
Known behavior: Appears to be a UTC timestamp representing the last time the game wrote data, though documentation notes its exact purpose is unclear.
Reasonable edits: Usually leave unchanged.
Suspicious edits: invalid timestamp text, empty value, dates before supported epoch, random text.

Field: CheatMode
XML path: SaveData.CheatMode
Observed example: false
Expected type: boolean
Known behavior: Whether Cheat Mode is enabled on the savefile.
Reasonable edits: true or false.
Suspicious edits: 0, 1, yes, no, text, empty value.

Field: AssistMode
XML path: SaveData.AssistMode
Observed example: false
Expected type: boolean
Known behavior: Whether Assist Mode is enabled on the savefile. Uses Assists child values to determine enabled assist mechanics.
Reasonable edits: true or false.
Suspicious edits: 0, 1, yes, no, text, empty value.
Related field: Assists.

Field: VariantMode
XML path: SaveData.VariantMode
Observed example: false
Expected type: boolean
Known behavior: Whether Variant Mode is enabled on the savefile. Uses Assists child values to determine enabled variant mechanics.
Reasonable edits: true or false.

- os = 2A Old Site, Resurrections
- osr = 2B Old Site, Black Moonrise
- cr = 3A Celestial Resort, Scattered and Lost
- crr = 3B Celestial Resort, Good Karma
- cs = 4A Golden Ridge, Eye of the Storm
- csr = 4B Golden Ridge, Golden Feather
- t = 5A Mirror Temple, Quiet and Falling
- tr = 5B Mirror Temple, Mirror Magic

Field: LastArea
XML path: SaveData.LastArea
Observed example: <LastArea ID="1" Mode="Normal" />
Expected type: attribute-only element
Known behavior: Last area/chapter the player opened or played. Chapter selection opens to this area.
Expected attributes:
- ID: integer-like area/chapter ID
- Mode: string mode name, such as Normal
- SID may exist in some saves
Reasonable edits: valid ID and mode values.
Suspicious edits: deleting attributes, changing to text content, invalid ID, unknown mode, negative ID.

AREAS SECTION

Element: Areas
XML path: SaveData.Areas
Expected type: list of AreaStats children
Known behavior: Chapter-specific progress data.
This section contains deeper per-chapter data such as chapter completion, strawberries, deaths, best times, hearts, cassettes, modes, and other detailed progress.
For BackDoor's beginner/global editor, it is reasonable to preserve Areas unchanged.

Glossary:
- Area means chapter.
- Mode means alternate side, such as A-Side, B-Side, or C-Side.

Rule:
If BackDoor is only editing global fields above Areas, preserve Areas exactly unless advanced chapter support is implemented.

EntityID:
- EntityID denotes a collectible of some kind, such as berries or keys.
- It usually appears as a child element under another parent.
- It has a KEY attribute.
- Suspicious edits: deleting KEY, replacing EntityID with text, changing KEY to an invalid-looking value.

Strawberries:
- Strawberries are stored as EntityID lists, normally inside AreaModeStats.
- Top-level TotalStrawberries should ideally match the sum of strawberries collected in chapter data.
- Suspicious edits: changing total strawberries without changing Areas strawberry data.

AI EVALUATION GUIDANCE

When evaluating a user edit:
1. Check whether the field's type matches the expected type.
   - Boolean fields should be true/false.
   - Integer fields should be whole numbers.
   - String fields should remain strings.
   - Lists should remain lists.
   - Attribute-only elements should keep their attributes.

2. Check whether the value is in a plausible range.
   - Counts should usually be non-negative.
   - Time should be a non-negative FileTime integer.
   - UnlockedAreas should be a plausible chapter count.
   - SummitGems should have exactly six booleans.

3. Check consistency with related fields.
   - TotalStrawberries should match or be plausible relative to chapter strawberry data inside Areas.
   - TotalGoldenStrawberries should be plausible relative to chapter data.
   - AssistMode and VariantMode relate to Assists settings.

4. Treat structure changes as more suspicious than value changes.
   - Replacing an XML list with plain text is suspicious.
   - Removing attributes from LastArea is suspicious.
   - Deleting Areas is suspicious.
   - Replacing Areas with simple text is suspicious.

5. Be transparent.
   - Celeste's save documentation is a work in progress.
   - If a field is undocumented or only partially documented, say confidence is limited.
