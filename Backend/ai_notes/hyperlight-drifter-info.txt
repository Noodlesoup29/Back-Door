HYPER LIGHT DRIFTER decoded save schema for edit checking. Educated guesses only, not official docs. Use mainly to check type/format preservation.

Format: decoded save is JSON. Simple fields are numeric flags/counts/IDs/coords/timers. Many strings are compact custom lists using +, =, &, >. Empty string can be valid for list fields. Numeric flags should stay 0/1, not true/false.

General invalid patterns:
- numeric flag -> anything except 0/1
- integer/count -> text, bool, decimal, negative unless original uses negatives
- decimal/stat -> text, bool, empty
- coordinate/checkpoint -> text, bool, empty, extreme value
- compact string -> boolean/number/random text, missing separators, malformed entries
- complex serialized string -> any structure/type change is suspicious

Compact/list fields:
mapMod: compact map state, pattern ID=value&>. Preserve separators.
scK: compact ID=value>.
permaS: compact permanent world/object states ID=value>.
cShells, cSwords, cCapes, healthKits, scUp, sc, skill, warp, wellMap, events, cues: + separated lists, often ending in +.
values: compact named globals, pattern ValueName=value>.
rooms: + separated room IDs visited/unlocked.
enemies, bosses, tablet, well, noSpawn: empty string or compact list.
destruct: complex destroyed-object list, pattern like objectID=roomID&value&>.
cl: very complex serialized state string with =,&,>, embedded values; preserve exact structure.

Numeric flags / small states:
fireplaceSave, tutHeal, eq00, specialUp, badass, cape, hasMap, drifterkey, CH, sword, halluc, compShell: usually 0/1 or small non-negative integer. Suspicious: true/false text, decimals, negative, text.

Counts / stats:
successfulCollectTimes, successfulWarpTimes, successfulHealTimes, charDeaths, gear, gearReminderTimes, gunReminderTimes, checkStash, healthUp: non-negative integers. Suspicious: negative, decimal, text, bool.
playT, dateTime, checkBat, checkAmmo: decimal numbers. Suspicious: negative where inappropriate, text, bool, empty, extreme.

Checkpoint/player state:
checkRoom: integer room ID; changing may spawn/load player in invalid area.
checkX, checkY: numeric checkpoint coordinates; extreme/wrong type suspicious.
checkHP: positive integer health at checkpoint; zero/negative/text/bool/huge suspicious.
checkAmmo, checkBat: numeric checkpoint resource values.
checkCID: integer checkpoint/entity/cell ID, may be negative; decimal/text/bool/empty suspicious.
checkStash: non-negative small integer state.

Other:
gameName: string save name, example GAME. Suspicious: empty, very long, control chars.
gear: likely currency count, non-negative integer.
healthUp: likely health upgrade count/state, non-negative integer or 0/1.

Evaluation rule: for Hyper Light, prioritize whether the edited value preserves expected type and string pattern. Be transparent that field meanings are guesses. Example: sword=1 is plausible; sword=true is suspicious because saves use numeric flags.
